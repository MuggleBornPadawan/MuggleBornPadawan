** clojure intro
- clojure language vs compiler
  - vm processes execute java bytecode
  - usually, the java compiler produces java bytecode from java source code
  - jar files are collections of java bytecode
  - java programs are usually distributed as jar files
  - the java program clojure.jar reads clojure source code and produces java bytecode
  - that java bytecode is then executed by the same jvm process already running clojure.jar

*** Keys
- continue next in out here eval inspect locals inject stacktrace trace quit
|----------+------------+----------------------------------+--------------------------|
| Key      | Name       | Job                              | Example                  |
|----------+------------+----------------------------------+--------------------------|
| c        | continue   | Run to end or next breakpoint    | Skip to result           |
| n        | next       | Go to next form, do not enter    | Step over (add x y)      |
| i        | in         | Enter inside function call       | Step into add            |
| o        | out        | Exit function, go back to caller | Leave add, back to total |
| H        | here       | Run to cursor point              | Stop at my cursor        |
| e        | eval       | Type code, see result            | e -> x -> 2              |
| I        | inspect    | Open value in inspector          | Inspect map              |
| l        | locals     | Show all locals + values         | See x=2 y=3              |
| (inject) | inject     | Change value mid-debug           | Set x=99 to test path    |
| s        | stacktrace | Show call stack, who called who  | total -> add -> +        |
| t        | trace      | Print each step to REPL          | Keep log for later       |
| q / Q    | quit       | Exit debugger, abort run         | Stop debug now           |
|----------+------------+----------------------------------+--------------------------|
*** Test code - tests all 12 keys
#+begin_src clojure
(ns example.core)

;; tree example/core.clj
;; (defn calculate-total
;;   "Calculates total price including tax."
;;   [prices tax-rate]
;;   (let [subtotal (reduce + prices)
;;         tax (* subtotal tax-rate)]
;;     (+ subtotal tax)))

(defn add [a b]
  (+ a b))

(defn calc-tax [subtotal]
  (* subtotal 0.2))

(defn make-order [user items]
  (let [subtotal (reduce + (map :price items))
        tax (calc-tax subtotal)
        total (add subtotal tax)
        order {:user user
               :items items
               :subtotal subtotal
               :tax tax
               :total total}]
    (if (> total 100)
      (assoc order :discount 10)
      order)))

(make-order "bob" [{:price 40} {:price 50}])
#+end_src
*** How to test each key here
- c (continue): run once to end, run again to next breakpoint on make-order.
- n (next): step over (map :price items), (calc-tax subtotal) without entering.
- i (in): on (calc-tax subtotal) press i to enter inside calc-tax. On (add subtotal tax) press i to enter inside add.
- o (out): after i into add or calc-tax, press o to jump back to make-order let.
- H (here): put cursor on (assoc order :discount 10), press H to run straight to discount branch.
- e (eval): press e, type subtotal, tax, total, (> total 100). Check values.
- I (inspect): press I on order map or items vector to open inspector. Good for nested map.
- l (locals): press l inside let to see user, items, subtotal, tax, total, order.
- inject: press inject, set total to 5 or 200 to force else / then branch without restart. Tests discount logic.
- s (stacktrace): press s while inside add or calc-tax to see make-order -> add -> +.
- t (trace): press t before c to log all steps to REPL. Check trace after run.
- q (quit): press q on (reduce ...) to abort run. Re-eval (make-order ...) to start again.
*** Which to use?
- Lost? -> l then s
- Want to skip? -> n
- Want detail? -> i
- Want test? -> e
* do things; crash course
** form
- a form is any expression that the reader translates into a data structure and the compiler evaluates
- (operator operand1 operand2 ... operandn)
- str concatenates text
- whitespace seperates operands
** comments
- line comment (;); form comment (#); (comment (block a b)); M-x comment-dwim (un/comment selected region)
** control flow
- basic control flow operators: if, do, when
  - use do when you want to execute multiple statements given a condition is true or false
  - use when if you want to do multiple things when some condition is true, and you always want to return nil when the condition is false
- nil, true, false, truthiness, equality, and boolean expressions
  - both nil and false are used to represent logical falsiness, whereas all other values are logically truthy
- boolean operators or and and
  - or returns either the first truthy value or the last value
  - and returns the first falsey value or, if no values are falsey, the last truthy value
** def var
- immutable; values are bound and not assigned
** data structures
- "string" 
- "\"string\"" > "string"
- maps: hash maps and sorted maps
  - map values can be of any type—strings, numbers, maps, vectors, even functions
- get to look up values

  - (:a {:a 1 :b 2 :c 3})
- vectors - similar to an array, in that it’s a 0-indexed collection
- lists - linear collection of values

** functions
  - clojure’s support for first-class functions allows you to build more powerful abstractions than you can in languages without them
  - those unfamiliar with this kind of programming think of functions as allowing you to generalize operations over data instances. for example, the + function abstracts addition over any specific numbers
  - by contrast, clojure (and all lisps) allows you to create functions that generalize over processes. map allows you to generalize the process of transforming a collection by applying a function—any function—over any collection
*** functions
- the docstring is a useful way to describe and document your code. you can view the docstring for a function in the repl with (doc fn-name)
- the number of parameters is the function’s arity
*** special form functions
in clojure, special forms are the fundamental constructs evaluated by the compiler rather than functions. they define the core language semantics. because they are not functions, you cannot pass them as arguments (e.g., you cannot `map` an `if`). common special forms include:
- `def` defines a var in the current namespace
- `if` the basic branching construct
- `do`: evaluates expressions in order, returning the last
- `let`: creates lexical bindings
- `fn`: defines an anonymous function
- `quote`: prevents evaluation of an expression
- `var`**: returns the var object (referenced by `#'`)
- `loop` / `recur`**: provides tail-recursive looping
- `try` / `catch` / `finally` / `throw`**: exception handling
- `monitor-enter` / `monitor-exit`**: java synchronization primitives
- `new`: instantiates a java class
- `set!`: sets the value of a mutable field or var

# Design Thinking Implementation Guide

This guide explains how to apply the 5-stage Design Thinking lifecycle across your portfolio projects.

---

## Stage 1: Empathize (`01-empathize.md`)

* **Goal**: Gain a deep understanding of the problem space and target users.
* **When to perform**: Before defining features or writing code.
* **Key Activities**:
  1. Interview potential users or map target domain challenges.
  2. Complete the Empathy Map (Says, Thinks, Does, Feels).
  3. Identify core user Pain Points and Gains.
* **Success Criteria**: A validated problem statement rooted in user needs rather than assumptions.

---

## Stage 2: Define (`02-define.md`)

* **Goal**: Translate user needs into explicit product requirements and project boundaries.
* **When to perform**: Right after user research and before technical architecture.
* **Key Activities**:
  1. Draft the Problem Statement (Point of View / POV).
  2. List Functional and Non-Functional Requirements.
  3. Clearly define In-Scope vs. Out-of-Scope items.
  4. Set measurable Success Metrics / KPIs.
* **Success Criteria**: Clear project scope that prevents scope creep.

---

## Stage 3: Ideate & Architecture (`03-ideate-architecture.md`)

* **Goal**: Design the technical solution, evaluate alternatives, and establish system topology.
* **When to perform**: Prior to implementation.
* **Key Activities**:
  1. Brainstorm candidate technical approaches.
  2. Record stack choices and rationale (pros, cons, trade-offs).
  3. Outline component relationships, API contracts, and data structures.
  4. Document security, performance, and scaling considerations.
* **Success Criteria**: Thorough technical specification ready for execution.

---

## Stage 4: Prototype & Build Plan (`04-prototype-build-plan.md`)

* **Goal**: Turn architectural decisions into an actionable, phased delivery plan.
* **When to perform**: Immediately before initiating development sprint/phases.
* **Key Activities**:
  1. Define MVP boundaries and iterative release milestones.
  2. Break work into granular, task-level checklists.
  3. Identify technical risks and draft explicit fallback / mitigation strategies.
* **Success Criteria**: Clear milestone roadmap with verifiable deliverables.

---

## Stage 5: Test & Evaluate (`05-test-evaluate.md`)

* **Goal**: Validate that the solution satisfies the initial problem statement and quality metrics.
* **When to perform**: During testing phases and post-launch.
* **Key Activities**:
  1. Run automated unit, integration, and manual acceptance tests.
  2. Gather feedback from user testing sessions.
  3. Evaluate performance against key success metrics set in Stage 2.
  4. Conduct a project Retrospective (What went well, What could improve, Action items).
* **Success Criteria**: Empirical verification of project quality and documented learnings for future portfolio iterations.
